# Личные данные каждого пользователя

Набор распространяет инструкции и локальные утилиты. В нём нет общего сервера, учётной записи для всех, сборщика API-ключей, телеметрии или автоматической отправки результатов авторам. Установка сама по себе не предоставляет владельцу этого GitHub-репозитория доступ к чужому устройству или проектам.

| Общее в публичном GitHub | У каждого пользователя отдельно |
| --- | --- |
| Тексты навыков, исходники утилит, синтетические тесты | Свой проект и выбранные для работы исходники |
| Шаблоны с примерами и пустыми значениями | Свои подключения GitHub, хостинга и других сервисов |
| Документация, лицензия и версии | Секреты в своём штатном менеджере секретов/учётных данных |
| Проверяемые перед установкой обновления | Отчёты, скриншоты и результаты в своём приватном хранилище |

Для скачивания публичного набора API-ключи и доступ к личным репозиториям не нужны. Для работы с GitHub или хостингом каждый подключает собственный аккаунт и выбирает только необходимые права и проекты. Подключения автора другу не передаются.

## Правила для помощника

- Используй проект, аккаунты и приватное хранилище текущего пользователя. При нескольких подходящих аккаунтах уточни цель; не выбирай автора набора как владельца результата.
- Рабочие результаты сохраняй отдельно от клона инструментов и папок установленных навыков. Никогда не отправляй код проекта, отчёты, скриншоты, ключи или данные клиентов обратно в этот репозиторий, его issues, PR или владельцу.
- Не проси вставлять ключи/пароли в чат. Не читай `.env`, cookies, SSH-ключи, хранилища учётных данных и весь environment ради настройки набора. Для интеграций используй штатный вход или защищённую подстановку секрета. В `.env.example` пиши имена и пустые значения.
- Не помещай чувствительные данные в поиск, URL, диагностику, примеры и публичные отчёты. `.gitignore` не защищает уже отслеживаемое содержимое или историю.
- Не добавляй телеметрию, скрытые загрузки или фоновую синхронизацию. Интеграции/аналитика создаваемого приложения должны обслуживать задачу его пользователя в выбранном им аккаунте.
- Общие папки и командные подключения выбираются владельцем данных явно. Для личной работы нужны отдельные аккаунты ChatGPT/Codex и приватные проекты; на общем компьютере — отдельные профили ОС. Навыки не изолируют людей, использующих один общий аккаунт.

Эти правила включены в каждый из 12 `SKILL.md` и сохраняются при отдельной установке одного навыка.

## Локальная работа и облако

Шесть Python-утилит работают с переданными файлами локально, без API-ключей, сети и внешних процессов. Их можно запустить в терминале и передать помощнику только очищенный результат. Результат может содержать выбранные входные данные: например, изображение сравнения или фрагмент предоставленного отзыва. Храни его так же приватно, как исходник; маскирование контактов не является полным обезличиванием.

Облачная модель, браузер, поиск и подключённые сервисы — отдельные каналы обработки. Переданный материал обрабатывается и может храниться выбранным провайдером по правилам аккаунта/рабочей области. Навык не меняет настройки хранения/обучения или доступ администратора. «Авторы набора не получают данные» не означает «данные никогда не покидают устройство».

Если нужна обработка строго только на устройстве, используй локальные утилиты без отправки содержимого в облако; для анализа моделью нужен отдельно настроенный локальный движок. Этот набор его не устанавливает и его изоляцию не проверяет.

Официальные сведения: [границы и обработка данных Work Cloud](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-cloud-security), [штатное хранение GitHub-учётных данных](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git).

См. [отчёт проверки](docs/privacy-review.ru.md) и `SECURITY.md`. Версия фиксируется commit SHA; автоматических обновлений нет. Инструкции помогают агенту соблюдать границы, но не заменяют права ОС, изоляцию среды или настройки провайдеров.
