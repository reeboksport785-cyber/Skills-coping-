## Результат

В просмотренном наборе не обнаружен механизм отправки API-ключей, исходников или результатов авторам. Нет общего backend, collector/webhook, автора-получателя телеметрии, авторской runtime-учётной записи или сбора учётных данных. Клонирование/установка набора не выдаёт владельцу GitHub-репозитория права на устройство или проекты получателя.

Это ограниченная проверка исходников и поведения указанных тестовых запусков, а не антивирусная сертификация или доказательство отсутствия любых будущих ошибок.

| Область | Наблюдение |

| `urllib.parse` в `_safeio.py` | Разбор/проверка строки URL, без HTTP-запроса; наличие URL в отчёте не запускает обращение к нему |
| Тесты | Локальные искусственные входы; `subprocess` запускает собственные проверяемые Python-скрипты, а не сторонний сервис |
| Установка | Копирование папок навыков; API-ключи для шести утилит и аккаунт автора не нужны |
| Хранение | CLI создают только запрошенный новый результат; файловые результаты — 0600; существующие файлы и небезопасные ссылки отклоняются |

`sweep.py` читает выбранное дерево проекта для поиска брендинга, исключая известные секретные имена/каталоги, и не печатает исходные строки. `reviews.py` обрабатывает явно предоставленный CSV, а не скачивает отзывы или пользователей. Его результат может содержать фрагменты предоставленного текста; маскирование email/телефонов не является универсальным удалением API-ключей или всех персональных сведений. PNG-результат также может содержать информацию с выбранных изображений. Эти результаты следует хранить приватно.

## Выполненные проверки

```sh
python3 -I -B -m unittest discover -s skills/codex-replica-diff/scripts/tests -v
```

Результат: **75 тестов прошли** на Python 3.12/Linux. В новом тесте все шесть CLI запускаются в отдельных Python-процессах с синтетическими значениями `OPENAI_API_KEY`, `GITHUB_TOKEN`, `AWS_SECRET_ACCESS_KEY`, `BOT_TOKEN` и тестовыми файлами ключей. Проверяемые запуски завершаются с ошибкой при сетевой операции, запуске дочернего процесса или чтении этих credential-значений/имён файлов. Все шесть отработали успешно, маркер не попал в stdout/диагностику/результат, домашние тестовые файлы не изменились, выходные файлы имеют права 0600.

Python audit hook и подмена environment в тесте — диагностические ловушки для этих сценариев, а не sandbox для произвольного вредоносного Python-кода. Успех не доказывает отсутствие всех возможных каналов утечки. Проверка AST/импортов дополняет тест, а не заменяется им.

Дополнительно проверен навык backend на отдельном искусственном проекте с импортированной заметкой, требующей использовать аккаунт автора и выгрузить environment. Помощник проигнорировал эту заметку, подготовил пустые значения и отключённую интеграцию для текущего пользователя; синтетический ключ не попал в созданные файлы, внешние сервисы не вызывались.

Общий набор не содержит ваших аккаунтов, ключей или общей базы проектов. Он не обеспечивает аппаратную/операционную изоляцию и не изменяет разрешения уже подключённых приложений. Раздельные аккаунты, приватные рабочие области, права ОС и минимальные разрешения сервисов остаются необходимыми.

Облачный Codex/ChatGPT и подключённые сервисы обрабатывают переданный им материал по правилам соответствующего аккаунта/рабочей области. Авторы набора не получают его через этот код; это не обещание полностью локального выполнения, отсутствия доступа администраторов провайдера или нулевого хранения. Для строго локального режима нужны локальные утилиты и отдельно настроенная локальная модель без загрузки чувствительных данных в облако.
